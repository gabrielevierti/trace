**Digital Evidence Correlation Engine**

TRACE is a local-first research toolkit for examining digital artifacts and turning fragmented observations into explainable evidence relationships.

It is deliberately conservative: an artifact is an observation; a relationship is an inference generated by an explicit rule; a finding is an indicator for human review. TRACE does not establish attribution, intent, guilt, or legal conclusions.

## What it does

- Hashes files with SHA-256.
- Detects basic file signatures and sample entropy.
- Parses Chrome History/Downloads and Safari History databases when available.
- Parses macOS LaunchServices quarantine events when available.
- Optionally ingests captured macOS unified-log text.
- Correlates browser visits, downloads and filesystem artifacts.
- Shows an interactive evidence graph, timeline, findings and evidence inspector.
- Records the basis and confidence of every inferred relationship.
- Creates an acquisition manifest and can verify evidence integrity.
- Generates JSON plus a standalone HTML report with no server or external assets.
- Includes a controlled demo and automated tests.

## Quick start

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .

# Analyze a real directory
trace analyze ~/Downloads --chrome --safari --quarantine
open trace-report.html
```

## macOS acquisition workflow

TRACE can collect supported user-readable artifacts into a case directory. It does not bypass permissions or security controls.

```bash
trace collect-macos --output CASE-001
trace analyze CASE-001/evidence/macos --chrome-path CASE-001/evidence/macos/History --case CASE-001
```

For an optional short unified-log capture:

```bash
trace collect-macos --output CASE-001 --logs --log-hours 1
```

Before analysis, the acquisition creates an evidence manifest containing SHA-256 hashes. Verification:

```bash
trace verify CASE-001
```

## Evidence model

```text
OBSERVED ARTIFACT
      |
      v
+----------------+
| source         |
| timestamp      |
| path / URL     |
| hash           |
| metadata       |
+----------------+
      |
      v
CORRELATION RULE
      |
      v
INFERRED RELATIONSHIP
      |
      +--> confidence
      +--> supporting basis
```

The distinction is intentional. For example, `Chrome recorded a download` is observed. `This filesystem object corresponds to that download` is inferred and must expose its supporting basis.

## Architecture

```text
Evidence sources
      |
      +-- filesystem
      +-- Chrome
      +-- Safari
      +-- macOS quarantine
      +-- optional unified logs
      |
      v
Artifact normalizer
      |
      v
Correlation engine
      |
      +-- filename
      +-- path
      +-- timestamp proximity
      +-- URL host + time
      |
      v
Findings + Timeline + Graph
      |
      v
HTML / JSON report
```

## Validation

The test suite is intentionally small but covers core hashing and correlation behavior. The next validation layer should use controlled evidence scenarios where expected artifacts and relationships are known in advance.

## Limitations

TRACE is a research/portfolio project, not a validated forensic examination suite. Artifact schemas change across OS/browser versions; permissions may prevent acquisition; timestamps can have different semantics; and absence of an artifact is not proof that an event did not occur. Do not treat automated confidence scores as statistical probabilities.

For any real investigation, preserve evidence using the procedures, tools, legal authority and chain-of-custody requirements applicable to the case.
